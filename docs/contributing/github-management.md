# GitHub 운영

**협업 규칙 초안**

적용 범위는 [협업 규칙 안내](../../CONTRIBUTING.md) 참고.

## 1. Project 관리

사용할 Project: [gagyebu](https://github.com/users/Hdev-x/projects/2)

- 목표·완료 조건은 Issue에서 관리
- 변경·검증은 PR에서 관리
- 진행 상태는 Project에서 관리

### 등록

- 기존 Project 재사용
- 작업마다 새 Project 생성 불필요
- 기능·작업, 버그, 논의 Issue 등록
- Issue가 있으면 관련 PR은 **별도 카드로 중복 등록하지 않기**
- Issue 없는 작은 수정은 PR만 등록
- New item에 제목만 입력한 Draft item은 메모
- 정식 작업은 Issue로 전환 후 관리

### 상태 변경

작업 시작·리뷰 요청·완료 시 담당자가 상태 갱신.

| 상태 | 전환 기준 |
|---|---|
| 할 일 | 작업·버그·질문 등록, 아직 착수 전 |
| 진행 중 | 조사·구현·논의 시작. Draft PR도 작업 중이면 이 상태 유지 |
| 리뷰 중 | 구현·검증 결과 기록, Draft 해제 후 상대방에게 리뷰 요청 |
| 완료 | 기능·작업·버그는 완료 조건과 검증 근거 확인, 관련 PR이 있으면 merge 확인. 논의는 결론 기록과 관련 문서·후속 Issue 반영 후 종료 |

- **일부 PR만 merge**: 남은 완료 조건 확인 후 상태 판단. 전체 작업 완료 처리 금지
- **중단·막힘**: Issue 댓글에 이유·남은 작업·재개 조건 기록
- 큰 재작업으로 Draft 전환 시 진행 중으로 변경
- **취소·중복**: 이유 기록 후 Issue 종료와 Project 항목 보관. 실제 완료와 구분
- **`Auto-close issue` 끄기**: 완료 조건 확인 후 Issue 종료. 보드 상태만으로 종료하지 않기

### View·일정

View는 같은 항목을 다른 방식으로 표시.

- 작업 목록(Table)
- 진행 현황(Board)
- 작업 일정(Roadmap)

날짜는 합의한 경우만 지정.

## 2. Milestone 관리

Milestone은 합의한 버전·단계의 목표와 필요한 작업 묶음.

작은 작업이나 날짜마다 생성 불필요.

### 생성

- 둘이 **목표·범위 합의 후** 생성
- 이름·목표·완료 기준 작성, 제외 범위는 필요한 경우 추가
- 마감일은 합의한 경우만 지정
- [작성 양식과 예시](examples.md#milestone-작성-양식) 참고

### 작업 연결·범위 변경

- 목표 달성에 필요한 Issue 연결
- 같은 작업의 PR은 중복 지정하지 않기
- Issue 없는 작업은 PR만 지정 가능
- 해당 목표를 막는 버그나 반드시 결정할 논의도 포함
- 목표·일정에 영향을 주는 작업 추가·제외는 합의 후 반영
- 관련 Issue에 변경 이유와 이동한 작업 기록

### 종료

- 포함한 **필수 작업 완료와 전체 사용 흐름 검증** 후 종료
- 일정 도달이나 표시상 100%만으로 종료 금지
- 취소·보류로 닫힌 Issue를 완료로 간주하지 않기
- 진행률을 높이려고 미완료 작업을 제외하지 않기

## 3. GitHub 설정 권장안

권장 설정이며 파일 작성만으로 적용되지 않음.

- Squash merge만 허용, merge 후 작업 브랜치 자동 삭제
- 지원 플랜이면 `main` Ruleset에 PR 필수, 승인 1명, 변경 시 기존 승인 취소, 미해결 리뷰 대화 차단, force push·삭제 차단
- Ruleset 미지원 시 같은 기준을 팀 약속으로 적용
- 안정적인 build·test·lint 명령이 생기면 PR Actions로 실행하고 필요한 검사 통과를 merge 조건으로 설정

자동화는 반복되는 누락이나 협업 문제가 생기면 필요한 부분만 추가.
