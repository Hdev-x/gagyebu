# 협업 작성 예시

[협업 규칙](../../CONTRIBUTING.md)

예시의 기능·검증 결과·번호는 실제 내용으로 변경

## 1. 기능·작업 Issue

- Issue 제목: `지출 등록 기능 구현`
- 예시 번호: `#3`
- 담당자: 구현할 팀원

```markdown
## 목표
금액·날짜·카테고리를 입력해 지출 저장

## 완료 조건
- [ ] 금액·날짜·카테고리 입력 가능
- [ ] 0원 이하 금액은 저장 차단
- [ ] 저장한 지출이 목록에 표시됨

## 제외 범위
- 지출 수정·삭제는 별도 작업
```

## 2. PR

PR 제목: `feat: 지출 등록 구현`

검증 내용은 실제 수행한 결과로 작성.

```markdown
## 변경 내용
- 금액·날짜·카테고리를 입력하는 지출 등록 화면 추가
- 0원 이하 금액 저장을 차단하고 오류 안내 표시

## 검증
- build 통과
- 등록 후 목록에 표시되는 것 확인
- 0원·음수 입력 시 저장되지 않는 것 확인

## 리뷰 요청
- 금액 검증과 오류 안내의 적절성 확인 요청

## 관련 Issue
Closes #3

## 확인
- [x] 변경 내용 검증 및 결과 기록
- [x] 변경 diff 확인 및 Secret·개인 환경 파일 제외
```

## 3. 버그 Issue

- 버그 Issue 제목: `월 변경 시 이전 달 지출이 표시됨`
- 라벨: `bug`

```markdown
## 현상
10월에서 9월로 바꿔도 10월 지출이 남아 있음.

## 재현 방법
1. 10월 지출 목록 열기
2. 조회 월을 9월로 변경

## 기대 결과
9월 지출만 표시

## 환경과 증거
- Chrome에서 발생
- 새로고침하면 정상 표시됨

## 완료 조건
- [ ] 선택한 월의 지출만 표시됨
- [ ] 월을 연속으로 변경해도 정상 동작
```

## 4. 논의 Issue

- 논의 Issue 제목: `사용자 카테고리 추가를 지원할까?`
- 라벨: `question`

```markdown
## 질문
기본 카테고리만 제공할지, 사용자 추가도 허용할지 결정이 필요함.

## 배경
사용자 추가를 허용하면 자유롭게 분류할 수 있지만,
추가·수정·삭제 화면과 관련 데이터 처리가 필요함.

## 선택지
- A: 첫 버전은 기본 카테고리만 제공
- B: 첫 버전부터 사용자 카테고리 추가 지원
```

### 결론 댓글

논의 후 결론 댓글 예시.

관련 문서나 작업 Issue에 반영 후 논의 Issue 종료.

```markdown
## 결론
- 첫 버전은 기본 카테고리만 제공하기로 합의
- 등록 기능을 먼저 완성하기 위해 사용자 추가는 보류
- 사용자 추가는 실제 필요가 생기면 다시 검토
- 기본 카테고리 적용 작업은 #8에서 진행
```

환경·현상·Issue 번호는 예시.

실제 확인한 내용과 생성한 번호로 작성.

## Milestone 작성 양식

제목은 `v0.1 — 기본 가계부 완성`처럼 버전·단계와 목표 작성.

마감일은 합의한 경우만 지정.

아래 양식을 GitHub Milestone 설명란에 복사.

파일만으로 자동 적용되지 않음.

### 복사용 양식

```markdown
## 목표
-

## 완료 기준
-

## 제외 범위
<!-- 없으면 삭제 -->
-
```

### 작성 예시

```markdown
## 목표
지출 등록과 월별 내역·합계 조회가 가능한 첫 버전 완성

## 완료 기준
- 포함한 기능의 Issue 완료 조건 충족 및 관련 PR merge
- 지출 등록 → 목록 조회 → 월별 합계 흐름 검증

## 제외 범위
- 지출 수정·삭제
- 수입 관리
- 사용자 카테고리 추가
```

관련 작업은 Issue의 Milestone 항목에서 지정.

작업별 체크리스트는 Issue에서 관리.
